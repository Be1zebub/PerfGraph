# Issue 2 — Correct critical-path timing semantics

## Problem

The extractor sums durations of all nodes in a critical-path tree, including
parallel branches, and presents the result as total chain length. This produced
75893 ms for a page whose deepest path is only 3 levels.

## Required change

Expose elapsed longest-path duration, aggregate request duration, page lifecycle
duration, and longest single request as distinct fields. Use only elapsed path
duration for user-wait and causal claims.

## Acceptance

Parallel branches never inflate `elapsedCriticalPathMs`; aggregate duration is
clearly labeled and never rendered as elapsed critical-path time.
