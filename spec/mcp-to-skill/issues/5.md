# Issue 5: тестирование, упаковка и release gate

## Цель

Доказать, что после удаления MCP CLI не деградировал, а опубликованный пакет
остаётся самодостаточным.

## План проверок

1. Запустить `npm run typecheck`.
2. Запустить `npm test`.
3. Запустить `npm run build`.
4. Проверить `node dist/index.js --help` и `node dist/index.js run --help`.
5. Выполнить smoke run на локальном или разрешённом тестовом URL с ограниченным
   timeout и проверить обязательные артефакты.
6. Проверить failure path на недоступном/невалидном URL.
7. Запустить `npm pack --dry-run` и убедиться, что в package contents нет MCP
   source, MCP tests или MCP SDK.
8. Выполнить финальный `rg` по `mcp`, `perfgraph_analyze`, `insights.json` и
   `report.json`, вручную классифицируя только исторические упоминания.

## Acceptance criteria

- Typecheck, tests и build проходят.
- Smoke run создаёт валидные agent-facing artifacts.
- Ошибка сбора имеет ненулевой exit code и понятное сообщение.
- Package dry-run не содержит MCP implementation/dependency.
- Не осталось активных docs/config references на удалённый MCP API.
- Результаты проверок зафиксированы в summary реализации.

## Ограничения

- Не использовать `npx` для установки новых одноразовых пакетов.
- Не выполнять deploy, публикацию npm или удаление пользовательских данных без
  отдельного подтверждения.
- Сетевые smoke-тесты должны иметь явный timeout и не блокировать workflow.
