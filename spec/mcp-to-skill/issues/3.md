# Issue 3: создать CLI skill для агентов

## Цель

Дать агенту компактную, практичную инструкцию по запуску CLI и анализу
результатов без MCP.

## Предлагаемая структура skill

- trigger: URL + performance/speed/Core Web Vitals/Lighthouse/bottleneck;
- prerequisites: Node.js, установленный `perfgraph` и Chromium;
- standard command:

  ```bash
  perfgraph run --url <url> --output ./perfgraph-output --pretty
  ```

- optional flags: `--runs`, `--device`, `--no-lighthouse`, `--no-coverage`,
  `--no-console`, `--no-dom`;
- read order: `insights.toon` → `report.toon` → `report.md`/`graph.toon` →
  summaries → raw files;
- interpretation: severity, confidence, evidence, causal chain, remediation;
- failure handling: exit code, stderr, warnings, missing artifacts;
- fallback: локальный `node dist/index.js` после проверки build, если бинарник
  не установлен.

## Interpretation workflow

После чтения артефактов skill должен направить агента через такие вопросы:

1. Каков executive status и есть ли ограничения данных?
2. Какие 1–3 causal chains имеют наибольший severity/priority?
3. Что в них является root cause, bottleneck и user impact?
4. Какие Core Web Vitals реально измерены, а какие выведены косвенно?
5. Есть ли конкретные URLs, selectors, durations или byte evidence?
6. Какие действия дадут максимальный эффект и как проверить результат?

Для 1–3 главных chains skill требует показать ASCII causal graph. Граф должен
быть проекцией `report.chains[].path`, а не новой гипотезой агента. Для каждого
перехода по возможности указывать confidence.

Финальный ответ должен быть коротким: статус, главные причины, цепочки
причина → impact, 3–5 действий, ограничения и следующий замер. Полный список
однотипных issues не нужен, если они относятся к одной chain.

## Правила для агента

1. Не заменять PerfGraph браузерной инспекцией или прямым Lighthouse, если
   запрос относится к PerfGraph.
2. Не считать Lighthouse score единственным диагнозом.
3. Не утверждать метрики, которых нет в отчёте/evidence.
4. Не читать raw trace/network первым шагом.
5. Не выдавать рекомендацию как доказанный root cause, если confidence слабый.
6. Указывать warnings и ограничения сбора в итоговом ответе.

## Acceptance criteria

- Skill содержит trigger, command, flags, read order и error handling.
- Инструкция не содержит MCP, JSON-RPC, resource URI или `perfgraph_analyze`.
- Агент по skill может получить от CLI итоговый диагноз и найти все нужные
  артефакты.
- Skill не дублирует код pipeline и не требует новых dependencies.
- Skill запрещает выдавать causal impact как напрямую измеренный пользовательский
  metric.
- Skill требует явно отмечать warnings, отсутствующие данные и ошибки сбора.
- Skill требует ASCII graph для главных causal chains либо явное сообщение, что
  chains отсутствуют.

## Не делать

- Не добавлять AI API в CLI.
- Не заставлять skill читать все raw-файлы по умолчанию.
