# Issue 2: закрепить CLI output contract

## Цель

Сделать набор CLI-артефактов и правила их чтения стабильным контрактом для
skill и AI-агентов.

## Затронутые области

- `src/cli/run.ts`
- `src/output/manifest.ts`
- `src/distill/insights.ts`
- `src/report/types.ts`
- `test/` для output/report integration tests
- README/skill documentation

## План изменений

1. Зафиксировать обязательные артефакты успешного `run`:
   `insights.toon`, `report.toon`, `graph.toon`, `report.md`, `manifest.toon`.
2. Зафиксировать optional raw artifacts и поведение при `--no-*` flags.
3. Проверить, что пути в stdout/stderr и возвращаемый exit code позволяют агенту
   найти output directory.
4. Добавить contract test на manifest/read order и ключевые поля report.
5. Уточнить документацию: TOON — текстовый формат, JSON-парсинг к нему не
   применяется.
6. Зафиксировать, что при частично неуспешных collector-ах итог содержит
   warnings и не скрывает неполноту данных.

## Acceptance criteria

- Успешный `run` создаёт обязательный набор файлов.
- `manifest.toon` перечисляет реально созданные файлы и рекомендуемый порядок
  чтения.
- `insights.toon` пригоден для первичного triage без открытия raw data.
- `report.toon` содержит summary, issues, chains и recommendations.
- Отсутствие optional collector не выглядит как успешное наличие его данных.
- Contract tests детерминированны и не требуют внешнего URL.

## Не делать

- Не переводить TOON обратно в JSON.
- Не добавлять новый transport/API только ради удобства чтения отчёта.
